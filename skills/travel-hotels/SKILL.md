# 住宿

## 1. 选址：住在动线重心，不是"市中心"

- 把每天要去的点标出来，选到各点平均移动最短的位置，优先地铁沿线。
- **尽量连住两晚以上**，避免一夜一换（换酒店是隐性的时间黑洞）。
- 抵达当晚、以及和不确定交通绑定的那一晚，优先选**可免费取消**的房型。

## 2. 三档候选，必须覆盖价格梯度

用户明确反馈过"最便宜的都要 600，太贵了"。所以：

- **至少 1 档是能住的整间房，均价 < ¥200/晚**（不是床位）
- **至少 1 档 < ¥400/晚**（舒适型 / 3–4 星）
- 再加 1 档舒适或品质档
- **查不到就如实写**"这一带整间房最低 ¥xx"，不要拿 ¥212、¥459 这种数字凑档。
- **即使用户要求"四星以上"，便宜档也要列**，标注"不符合你说的四星，只作价格参照"，让他知道底下还有什么选择。
- **每档给具体酒店 + 具体房型**，不要只说"某连锁"。
- **档次标签按真实档次起名**（省钱连锁 / 舒适升级 / 品质精选 / 海景豪华），别用泛泛的"经济/舒服"——实测出现过"品质"指向 ¥517 的高档型、"舒服（推荐）"却指向 ¥564 的豪华海景房，用户一眼就看出不对。

### 找便宜整间房的打法

- ⚠️ **别用飞猪 `--sort price_asc` 找便宜房**：会被青旅床位淹没（实测苏州平江路按价格升序，前 10 全是 ¥24–56 的青旅/公寓，很多还在苏州站，离景区很远；`--hotel-types hotel` 也过滤不掉）。
- ✅ **用途牛并带价带**：`tuniuHotelSearch` 传 `poiName:"平江路"` + **`prices:"100-260"`**。途牛每条结果带 `roomName`（房型）+ `roomArea`（面积），能一眼区分"大床房"和"床位"。实测同一片区返回如家商旅 ¥160（大床房 15–19㎡、4.7 分）、白玉兰商务 ¥208、凯里亚德 ¥221。
- 用飞猪找便宜房时，把 `--max-price` 放宽到 400 左右再自己挑可识别的经济连锁（如家/汉庭/7天/锦江之星/尚客优/白玉兰）。
- ⚠️ **写清是"床位"还是"整间/晚"**：青旅 ¥35 通常是床位/人。报床位就同时给该店整间房最低价，并注明"2 人需 ×2 或订整间"。
- ⚠️ **平台星级不可靠**：实测途牛把如家商旅、白玉兰都标成"高档型"。判断档次看**评分 + 房型 + 面积 + 点评摘要**。

## 3. 途牛配额紧（5 次/分钟、50 次/天）：1 次搜索 + 本地排序 + 只对 Top 3 拉详情

途牛 `tuniuHotelSearch` **没有排序参数**（参数只有 `cityName / checkIn / checkOut / adultNum / childNum / childAges / keyword / poiName / prices`），返回的是它自己的默认序，但排序要用的字段都给了：

1. **1 次调用筛出候选**：`poiName` 传动线锚点（"王府井""春熙路"），结果会集中在附近；`prices` 传预算带（如 `"600-1200"`，软过滤）。每家都带 `commentScore` 评分、`starName`、`lowestPrice`、`business` 商圈、`commentDigest` 点评摘要、`brandName`、`roomArea`、`roomWindow`、`meal`、`refund`、`firstPic`、经纬度。
2. **本地排序**（不花配额）：按「评分 → 星级 → 与锚点是否同商圈 → 价格是否在预算带」综合排，挑 3 家。三档就按三个价带各搜一次。
3. **只对选中的调 `tuniuHotelDetail`** 拿房型与图片，调用之间 `sleep 13`。
4. 撞限流就等 1 分钟再试，别连打；失败如实告诉用户，不要拿旧数据假装是新的。

## 4. 房型实拍图（用户要看"房间长什么样"）

**只用房型实拍**（床、卫生间、窗景）。用户原话："酒店大门的照片有啥好看的"。

- **来源只有一处**：途牛 `tuniuHotelDetail` 的 `roomTypes[]`——每个房型有 `roomTypeName` / `bedType` / `roomSize` / `maxOccupancy` / `floor` / **`images[]`**；`ratePlans[]` 给 `rmbPrices` 价格、`mealText` 早餐、**`cancelText` 免费取消截止**、`count` 余量。图要和该房型（房型名/面积/床型）对应上。
- ⚠️ **飞猪 `mainPic` 是门面/外景照，不是房型图**，不要拿它当房型图。
- **拿不到房型图就不放图**，宁可空着也不要拿门面照或大堂照充数。

### ⚠️ 途牛图片默认是 180×180 缩略图，要把尺寸后缀整段删掉

从 URL 末尾删掉 `_w…_h…_c…_t…_q…` **一整套（连 `_q70` 一起删）**，只留 `.jpg`：

```bash
echo "$URL" | sed -E 's/_w[0-9]+_h[0-9]+_c[0-9]+_t[0-9]+_q[0-9]+\.jpg$/.jpg/'
```

| 写法 | 结果 |
|---|---|
| `…hash.jpg`（后缀删干净） | ✅ 200 · 800×600 或 1236×914 |
| `…hash_q70.jpg`（只删一半） | ❌ HTTP 503，取不到图（最容易踩的坑） |
| `…hash_w180_h180_c1_t0_q70.jpg`（原样） | ⚠️ 只有 180×180，页面上明显发虚 |

下载后验尺寸：`file -b "$FILE"` 应是 800x600 / 1236x914，若是 180x180 就回去重下。

### 落地：先下载到本地，再内联成 base64

```bash
curl -s -o _tmp/room1.jpg "https://m.tuniucdn.com/....jpg"     # ① 一定先下载到本地（最容易被跳过）
```
```python
# ② 缩到够用的尺寸  ③ 转 base64 内联
from PIL import Image; import io, base64
im = Image.open('_tmp/room1.jpg').convert('RGB')
if im.width > 1200:
    im = im.resize((1200, int(im.height * 1200 / im.width)), Image.LANCZOS)
buf = io.BytesIO(); im.save(buf, 'JPEG', quality=82, optimize=True)
uri = 'data:image/jpeg;base64,' + base64.b64encode(buf.getvalue()).decode()
```

**两条硬禁止**：① 不要把 `<img src>` 写成酒店图床的 `https://…`（图床一挂就没、预览器里常是空白）；② 不要用"同目录子文件夹 + 相对路径"（沙箱预览器加载不到，文件单独发出去图也全丢）。

## 5. 用高德核实位置（别信"近地铁"文案）

```bash
# 拿酒店坐标（途牛结果自带经纬度，或 searchPOI 查），再搜周边；--center 是 lng,lat，不带方括号；--radius 单位米
amap-gui searchPOI --keyword "地铁站" --center 120.634556,31.313969 --radius 1000
```

返回的每条 POI 带 `distance`（米）、`type`、`address`、`tel`。实测平江路 1 km 内查出悬桥巷 522 m、相门 617 m、临顿路 706 m——**用实测距离写进候选卡**，比宣传语可信。同法还能查：酒店片区的密度（搜「酒店/民宿/客栈」）、停车场/充电桩（自驾）、便利店/医院/药店（带老人小孩）。

## 6. 每个候选卡要呈现什么

房型实拍图 + 酒店名 + 商圈与最近地铁站（实测距离）+ 参考价（每晚 / 总价，几人）+ 房型（名称/面积/床型/可住人数）+ 早餐 + **免费取消截止时间** + 评分与一句点评摘要 + 一句"为什么选它/它的代价"。候选之间**只列差异**，不要每档写一大段。

## 7. 自检

- 三档里有 < ¥200 和 < ¥400 的整间房吗？床位和整间写清了吗？
- 每张酒店图都是对应房型的实拍原图（不是门面照、不是 180×180 缩略图），且已内联？
- "近地铁"用高德实测距离核实过了吗？免费取消截止时间写了吗？
- 档次标签和真实档次对得上吗？

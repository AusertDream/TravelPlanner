# 路书网页交付

工具都在 `~/.dsh/preset-assets/travel-planner/`，下面记 `V=~/.dsh/preset-assets/travel-planner`。地图见 `travel-maps`，酒店卡见 `travel-hotels`。

## 1. 交付形态

- **一个 HTML 文件**，写到工作目录，中文文件名（`成都3天2晚路书.html`）。**不要套固定模板**，按这次行程的实际内容组织，只放必要信息。
- **联网看是正常的**：允许 CDN 库、地图瓦片等外部 HTTPS 资源（"完全离线单文件"是伪需求，没网连 AI 都调不了）。
- **唯一真正要避免的是相对路径兄弟文件**：`<img src="xxx.files/a.jpg">` 在沙箱化预览器里加载不出来（用户只看到空白图位），HTML 一转发也失效。图片一律 **base64 内联**（或绝对 HTTPS 链接，但图床会挂，酒店图必须内联）。
- **排版别做出"AI 生成感"**：动手前先加载 `design-taste-frontend`（可选技能，没装就跳过这句），**只取它的排版、留白、克制配色和"反模板"原则**，跳过 hero / sticky-stack / 滚动动画这类落地页骨架。常见 AI 味：紫色渐变、居中大标题、千篇一律的圆角阴影卡片、每段挂 emoji、满屏徽章。路书里：系统字体栈 + 字号层级，一个主色 + 中性灰，信息用表格/紧凑列表承载，重点靠字重和留白而不是色块。
- **临时文件放 `_tmp/`，交付前不清理**（绝不 `rm -r`，见 `travel-planning` §6）。

## 2. 页面骨架（从上到下）

1. **封面 + "这趟的逻辑"**：主标题、日期、人数、预算、一行地点串，然后**一段话说清这趟为什么这么排**（锚点是什么、关键取舍是什么，例："飞过去不到 3 小时，比高铁快 8 小时还便宜近一半，省下的钱够在太古里住两晚"）。**这一段是整份路书的灵魂。** 关键项标【需你自行预订】/【已确认】/【可选】。
2. **关键数字卡（4 个左右）**：大数字 + 一行小注（`2 晚` / `¥1,158 往返机票` / `3h05m 单程` / `≈¥2,200 人均`），3 秒抓住规模。
3. **吸顶导航**：各章锚点排成一行可横滑的小标签。
4. **总览地图**（`travel-maps`）。
5. **大交通**（`travel-transport`）、**住哪**（`travel-hotels` 的三档候选卡）。
6. **逐日行程**：每天一个章节，时间轴呈现（§8）；每项写时间窗、地点、做什么、**这段怎么走（几号线几号口 / 打车多少公里多少钱）**、实测时长、费用、预约/贴士；地址写到能直接导航并补一句地标（"××商场对面"）。每天附当日动线地图（`real_route`）和一行 **Plan B**。按地理分区组织时，**每区一个主题色**贯穿地图标记、章节标题、卡片边线。
7. **专题章节**：现在就该做的事（`travel-constraints` 的预约倒排表，按紧迫度排）· 花多少钱（§7）· 吃什么 · 天气（§7）· 备选路线（主方案之外的常见调整及各自代价）· 应急与提醒。
8. **页脚：数据来源**（§6）。
9. **交通细节**：航班号/三字码/航站楼/起降时间/行李额，火车车次/席别/历时；**PNR 与订单号留空标「预订后回填」**。

## 3. 篇幅：聊天简短，网页克制

- **聊天回复别长篇大论**：一句结论 + 文件路径 + 真正需要用户知道或拍板的事（马上要抢的票、行李额陷阱、需要他选的那一档）。**不要把网页内容在聊天里再讲一遍**，没有值得单独说的就短短几行。
- **网页只放必要信息**：速览 + 候选 + 每日行程 + 行动清单 + 预算 + 应急就够，不写成产品说明书。
- 用户明确要 Markdown / 打印稿 / "就要一张表"时再给。

## 4. 多候选怎么呈现

- 初版**不替用户拍板**：路线 2–3 套（"精华版/深度版""省心版/省钱版"），酒店 3 档。各写清取舍（多花多少时间、多少钱、放弃什么）。
- 用标签页或并列卡片切换，**候选之间只列差异**，不要因为多候选就变长。
- 用户选定后再收敛成最终版；没选就保持候选形态。

## 5. 文案：说人话，去掉 AI 味

- **禁用词**：约束项、约束条件、赋能、闭环、抓手、颗粒度、对齐、拉通、沉淀、复盘、心智、痛点、场景化、一站式、全方位、助力、打造、深耕、布局、生态、矩阵、维度、链路、漏斗、兜底、校验、沉浸式、仪式感、氛围感、拉满、干货、宝藏、避雷、保姆级、全网最全、吐血整理。→ 换成具体的人和事：不说"交通约束项"，说"哪天到、几点关门、票什么时候放"。
- **删空话**：精心打造、不容错过、令人惊叹、完美结合、别具一格、美不胜收、值得一看 → 换成具体细节（"从窗户能直接看到故宫屋顶"）。
- **具体优先**：说"卤煮、炒肝、炸酱面"，不说"品尝地道特色美食"；说"¥626 二等座、4 小时 24 分"，不说"交通便利、价格实惠"。
- 不要"综上所述 / 让我们来看看"这类过渡句；整页 emoji 和感叹号最多 1–2 个（⚠️ 这种真需要的）。
- 标题要具体："现在就该做的事" ✅ ／ "行程概要说明" ❌。
- 写完通读一遍：放到别的路书里也成立的句子就是废话，删掉或改具体。

## 6. 数据来源：逐条标在事实旁边

- **联网搜到的事实**（免票政策、放票时间、开放时间、赛程、交通管制、"必吃"推荐）：正文里在事实后加**上标序号** `<sup>1</sup>`（或小标签 `〔杭州市政府〕`），页脚「来源」列表按编号列：机构/站点名 — 标题，`href` 放真实链接，**可见文字里不出现 URL**，末尾附访问日期；同一来源复用同一编号。
- **工具实时查到的数据**（12306、飞猪/途牛价格、高德距离时长）：在「数据说明」里写**工具 + 查询日期**（"房价：途牛/飞猪（2026-10-02）"）。
- **自己的估算**（餐饮人均、打车费）：标"估算"。
- ⚠️ 只在页脚写一句"数据来自××官网"**不算标注**——读者不知道哪条事实出自哪。`<sup>` 少于 5 个通常就是在敷衍。
- ⚠️ **边查边记**：每次 `web_search` / `web_fetch` 后立刻记下「事实 → 来源名 → URL → 日期」。事后回忆只会漏、会错，给错来源比不给更糟。

## 7. 天气预报卡与预算环形图

**天气**：按预报 App 的样子，不要写成一句"15–25℃"。
- 横排日期卡（`周五 10/16`）：图标 → 最高/最低温 → 天气短语 → 降水概率（💧 40%，这才是决定行程的关键）。可加一条竖向温度色带看冷暖走势。
- 超出预报窗口的日子标明"历史同期"及年份；写一句"预报有不确定性，出发前 1–2 天再复核"；加一行穿衣建议。数据源规则见 `travel-constraints`。

**预算**：环形图 + 明细表，两层口径分开（用户明确要求）。
- **硬开销**（预算主体，全部来自查询，逐项标来源与日期）：机票/火车 + 酒店 + 能查到的门票。
- **参考估算**（单列，**不并入硬开销小计**）：餐饮、购物、市内交通（打车费）等。
- 给两个小计，写清估算只是参考；按几人算、不含哪些项也写清；给区间（节省版 ↔ 舒适版）更好。
- 环形图用 `conic-gradient` 或 SVG `stroke-dasharray`，中心放合计；颜色跟整页主题色一致，估算项可用浅色或虚线边框区分。纯 CSS/SVG 足够，不用引图表库。
- 外币一律用 `convert_to_cny` 换算。

## 8. 时间轴与动效

- **每日时间轴**：每个时段一个节点，写时间窗 + 地点 + 做什么；**交通段用不同底色**，一眼看出这天有多少时间在路上；顶部可加一条当天时间进度条（一个 `div` + `width:%`）。
- **动效只引导视线、不阻碍阅读**：滚动淡入（`IntersectionObserver` + `transition`）、节点依次点亮可以；不引动画库、不做要等它演完的动效。没 JS 或打印时内容必须完整可见。
- three.js 只在用户明确要 3D 时考虑（WebGL 在沙箱预览器里不一定能跑）；Remotion 产出的是视频，是另一条交付线，要先跟用户确认。
- 值得抄：勾选状态存 `localStorage`（不上传）；暗色模式（`prefers-color-scheme` + 手动切换，CSS 变量两份色板）；中文标题可用宋体（`"Noto Serif SC","Songti SC",serif`），数字用等宽便于对比。
- 不要做：引 Google Fonts（国内加载慢、常被墙）；用 OSRM 等境外服务算国内距离；向用户索取订单确认号/PIN/证件号（我们不代订，不该收这些）。

## 9. 景点配图：`photo-fetch.py`（Unsplash）

```bash
python $V/photo-fetch.py --outdir _tmp/photos --candidates 3 --names "竹林" "苏式园林" "江南水乡"
```

- 需要 `.env` 的 `UNSPLASH_ACCESS_KEY`（申请：https://unsplash.com/developers → New Application → Access Key）；脚本自己读 `.env`。免 key 网页端已返回 401；免 key 备用是 `--source wiki`（Wikimedia）。
- ⚠️ **Unsplash 是氛围图库，不是实景图库**：搜具体地名基本没用（"莫干山"搜出通用高山草甸，`Moganshan` 直接搜不到）。**搜题材词**：`bamboo forest China`、`water town China`、`Chinese classical garden`、`hotpot`、`misty mountain forest`。要"就是那个地方"的实景，用 `--source wiki` 或用户提供的照片。
- 搜到什么就用什么，不用逐张校验；不展示作者署名（用户要求）。图片内联或用 Unsplash 的 HTTPS 链接都行，别用相对路径。

## 10. CSS 护栏与三大事故

**每个 HTML 都要有**：

```css
*{box-sizing:border-box}
section{height:auto}              /* 章节高度永远由内容决定，见事故一 */
img{max-width:100%;height:auto}   /* 漏写这条，宽图会横撑出屏；img 永远不写死 height */
```

**事故一：`id` 撞名 + 固定高度 → 整章溢出盖住后面所有章节。** CSS 写了 `#map{height:460px}`，而章节恰好是 `<section id="map">`，整章被钉在 460px，2049px 的内容溢出去压住后面的章节，DOM 和坐标看起来全对。规则：章节类容器（`section`/`main`/`article`）永远不写固定 `height`；容器 id 避开章节名（叫 `#route-map` 别叫 `#map`）。

**事故二：删代码块时把 `})();` 一起删了 → 整页按钮全失灵。** 一个 `(function(){` 没闭合，整段 JS 语法错误，一行都不执行，用户以为"到处都是假按钮"。看到"所有按钮都没反应"，先跑交付门禁查 JS 语法，别逐个按钮排查。动过结构（删块、改 id）必须重跑。

**事故三：`flex-wrap` 的格子用 `border-right` 当分隔线 → 换行后变成悬空的"乱飞网格线"。** 改用 `div+div{border-left:…}`（除首项）并加大 `flex-basis`。

## 11. 交付门禁（不通过不交付）

```bash
bash $V/deliver-check.sh "成都3天2晚路书.html"
```

一条命令跑完：① 静态检查（标签配对、内联 JS 语法、CSS 括号、`#锚点`/`getElementById` 引用、图会不会被放大、章节写死高度）② 桌面 1371 与手机 390 两种宽度的布局检查（遮挡、溢出、零尺寸容器、横向溢出）③ 内容检查（地图是否用了 map-widget、有没有真实路线、占位词、体积）④ 首屏截图 `<路书>.check.png`。

- **返回 ✅ 才交付**，并用 `read_image` 看一眼截图——grep 查不出"图盖住了字"。
- 有问题就改，改完**再跑**，直到干净。门禁报的若确实是误报（比如你确认是第三方组件内部），在交付回复里说明，别为了让它变绿去改坏页面。
- 想看某一块：`node $V/shot.mjs "file:///D:/…/路书.html" "#days" out.png`（正常视口按元素裁切；不要用超长视口截图再按坐标判断重叠，超长视口下布局不同，会误判）。

## 12. 自检（网页层）

- 打开 5 秒能读出"去哪、住哪、下一步做什么"吗？"这趟的逻辑"写了吗？
- 图片全是 base64 内联、没有相对路径？酒店图是房型实拍？
- 联网事实逐条标了来源、正文里没有 URL？工具数据写了工具 + 日期？估算标了"估算"？
- 文案像人说话，没有禁用词？
- 天气是预报卡、写了不确定性？预算是环形图 + 明细、两层口径分开？
- 位置/路线都上了图？逐日有时间轴？
- `deliver-check.sh` 返回 ✅，截图看过了？
- 聊天回复简短、没把网页抄一遍？

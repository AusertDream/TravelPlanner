# 地图与真实路线

**表格说不清"在哪"。** 只写"充电桩在换乘中心 38 m、停车场 20 m"，读半天也没有空间感；标在地图上 3 秒就懂。**位置、路线、时间**这三类信息优先上图，文字作补充。

工具都在 `~/.dsh/preset-assets/travel-planner/`，下面记 `V=~/.dsh/preset-assets/travel-planner`。

## 1. 一律用 `map-widget.py`

```bash
bash $V/run.sh python $V/map-widget.py --spec d1.json --out d1.frag.html   # 必须经 run.sh，才拿得到高德/Google 的 key
# 把 d1.frag.html 的内容原样放进路书对应位置（自带 <style> 和 <script>，同页多张互不冲突）
```

**spec**：

```json
{
  "id": "map-d1",                  // 同页多张图必须不同
  "title": "第一天", "width": 1040, "height": 600,
  "real_route": "transit",         // transit | drive | walk | ride：按 points 顺序逐段要高德真实路线
  "city": "成都",                   // 公交规划需要
  "mode": "transit",               // 导航链接默认方式
  "label": true,                   // true 全标名字 | "key" 只标 key:true 的点 | false 只留编号
  "caption": "一句图注",
  "points": [                      // 按游览顺序写
    {"name": "成都天府国际机场 T2", "lng": 104.447, "lat": 30.3125, "type": "start"},
    {"name": "亚朵S酒店（东糠市街1号）", "lng": 104.084, "lat": 30.651, "type": "hotel"},
    {"name": "宽窄巷子", "lng": 104.0573, "lat": 30.6697, "type": "poi", "leg": "transit"}
  ]
}
```

（`//` 后面是说明，写进 json 文件时要去掉。）

- `type` 决定颜色：`hub` 换乘枢纽、`charge` 充电、`park` 停车、`hotel` 住宿、`poi` 景点、`food` 餐饮、`start`/`end` 起终点、`other`。
- `leg`：这一站"从上一站过来"的方式，覆盖 `real_route`（某段走路就写 `"leg":"walk"`）。

### 真实路线 `real_route`

组件按 points 顺序逐段调高德 JSAPI（`amap-route.mjs`，同一把 AMAP_KEY）拿**真实折线**：图上画真实走法（蓝=地铁、绿=公交、紫=铁路、灰虚线=步行、红=驾车），地图下的清单里每站自动写「公交地铁 6.1 km · 44 分钟 · 票价 ¥2 · 地铁2号线（钟楼→小寨）」。

**这些里程/耗时/票价是实测数据，行程正文和预算里的市内交通直接用它们。** 某段查询失败会退回灰色虚线直线并在清单里写明原因。

单独查一段：

```bash
bash $V/run.sh node $V/amap-route.mjs --from 108.9423,34.2610 --to 109.2785,34.3841 --mode transit --city 西安
# 多段：--legs legs.json --out routes.json；输出 distance/time/cost/tolls/segments(线路、上下车站)/path
```

> 为什么不用 `amap-gui route`：它在容器里画得出路线，但 CLI 只返回文字步骤，不返回坐标。

### 离群点自动处理（`"focus": "auto"`，默认）

一天里有个点离其它点特别远（典型：机场离市区 70 km），它不参与框选——地图照样聚焦市区、街道名能读，那个点在图边显示成「↘ 成都天府国际机场 T2 · 直线 51 km」，清单和路线照常。要把所有点硬框进一张图写 `"focus": "all"`（只给跨城走向图用）。

### 页面上会发生什么（自动降级，任何一层失败都留着静态图，绝不白屏）

| 层 | 什么时候 | 用户看到 |
|---|---|---|
| 0 静态底图（永远在） | 一打开 | 高德瓦片底图（2× 清晰度）+ HTML 画的点位与中文名（可点开高德）+ 路线 |
| 1 Google Maps JS API | `.env` 有 `GOOGLE_MAPS_API_KEY` 且连得上 Google（**滚到这张图时自动加载**） | 可拖动缩放的 Google 地图，中文标注 + 真实路线 |
| 2 Google 无 key 嵌入 | 无 key 但连得上 Google（点按钮） | 路线嵌入，所有站按顺序串起来；点清单里的地名会定位 |
| 3 Leaflet + 高德瓦片 | 连不上 Google（**境内普通用户的常态**） | 可拖动的高德底图，免 key |
| 4 只剩静态图 | CDN 也不通 | 一句提示，静态图本身是完整的 |

- 在线层要等**瓦片真的加载出来**才切过去，10 秒没出来就放弃这层；整页多张图共用一次 Google/Leaflet 加载。
- 图下方自动附**编号清单**：每站有「高德 / Google / 从上一站导航」链接，手机上直接唤起 App。
- 标注会按实际显示宽度避让：手机上撞在一起的点合并成「1·2」，放不下的名字只显示编号（清单里有全名）。
- **整页只交付一个 HTML**，不要为了"怕 Google 连不上"再做一份备用版——降级是组件自己做的。

### 坐标与 Google key

- **坐标一律 GCJ-02**（高德 `searchPOI` 返回的原样，别混 GPS 原始坐标）。Google 在中国大陆的**道路图**本身就是 GCJ-02 底图，直接用不偏；境外点高德给的就是 WGS-84，同样直接用。**别切卫星图**（WGS-84，会偏几百米）。
- **Key 会写进 HTML**（Maps JS API 的 key 天生前端可见）：Google Cloud 控制台里要 ① API 限制只勾 Maps JavaScript API；② 设每日用量上限；③ **不要加"网站"限制**——路书用 `file://` 打开，没有 Referer，加了就报错。给别人转发、不想带 key 的版本，生成时加 `--no-google-key`。

## 2. 标注规则

- **标地名，不要只丢编号**：写 `新国线黄山换乘中心` / `黄山北站` / `南大门立体停车场P1` / `全季酒店(换乘中心店)` 这样的真名字。点位真挤成一团时才用 `"label": false`，名字放清单里。
- **图例必须是中文**（换乘枢纽 / 停车场 / 充电桩 / 住宿 / 景点），不能出现 `hub` / `park` 这种键名。
- **一张图 6–8 个点为宜**；更多就拆成不同尺度的几张：

| 图 | 尺度 | 装什么 |
|---|---|---|
| 全程走向 | 跨城（z≈8–9） | 起点→终点 + 途经城市；`"focus":"all"` |
| 每日动线 | 城区（z≈13–14） | 当天的点 + `real_route` |
| 点位细节 | 百米级（z≈17–18） | 充电桩、停车场、地铁口、具体路口 |

## 3. 只要一张图片时：`map-render2.py`

塞进对比卡片之类、不需要交互时才直接出图（spec 同上，不支持 `real_route`）：

```bash
python $V/map-render2.py --spec spec.json --out map.jpg
```

**尺寸规则：`width` = 页面上的显示宽度，文件自动 2 倍（`hd`，默认 2）**：

| 图怎么放 | `width` | 文件像素 |
|---|---|---|
| 单栏通栏（最常见） | **1040**（= 页面栏宽，别多给） | 2080 |
| 双栏并排 | 每张 500 | 1000 |

- 缩放级按显示尺寸挑、瓦片 1:1 拼，底图地名就是高德网页上的原始字号。旧版"按 4 倍画布挑缩放级再缩小 4 倍"会把底图地名缩成芝麻粒（用户原话："除了自己标上去的，背景地图上的字啥都看不清"），已修掉。
- `width` > 1100 会告警（被页面缩小后底图字跟着变小）。想看更多街道细节用 `"zoom_bias": 1` 或拆局部图，**不要加大 width**。
- `"zoom"` 强制缩放级；`"print_bounds": true` 输出 `BOUNDS`（`cssW/imgW/hd/zoom/x0/y0`），自己做叠加层时必须用它，手推一定错位。
- 地图一律通栏，别塞进 `1fr 1fr` 双栏；`img` 不写死 `height`；出图后 base64 内联。
